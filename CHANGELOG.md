# NOOBTOPIA changelog

## 2026-11-03

- **feat(wire): the lighting matrix and the material vocabulary actually reach the engine now.** Both modules were pure and nothing applied them, which is a merger that stops one inch short. `src/wiring.lua` is the decision layer between them and Roblox: `lightPlan(scene, studs)` turns a resolved scene into the property assignments a Lighting service takes (`FogEnd` only when the place published a visibility reading -- a clear sky and a missing sensor are different facts, and the plan reports `kept_fog` instead of inventing a distance), `surfaceForPart` reads a part's explicit `SHANKPIT_Surface` attribute or falls back to a name convention (mirror / metal / glass / nothing), and `applySurface`/`applyFixture` write `Reflectance` and `Brightness` into duck-typed targets -- so every branch runs under plain Lua and `src/noobtopia.lua` is left with only a `Color3` wrapper. The host now publishes weather as `SHANKPIT_*` attributes, ticks the environment four times a second, re-scans materials every five seconds (writing only when a surface id changes), and drives any `PointLight` carrying `SHANKPIT_LightStyle`. **Two real bugs came out of the last mile, both in the modules rather than the wiring:** `Lighting.roblox()` clamped brightness to 1.0 while the matrix's exposure runs 1000..1936 permille -- it LIFTS the low end -- so the clamp silently deleted the compensation and handed a storm the same brightness as a clear sky; and `src/material.lua` conflated the REFLECTION axis (0 mirror, 1 metal, 2 glass) with the ANIMATION-kind axis (0 plain, 1 scrolling, ...), so `reflectance(Material.PLAIN)` read as "the mirror". Both axes are named apart (`MIRROR`/`METAL`/`GLASS`/`OTHER` vs `KIND_*`); they share the integer 0 by design, so the test pins that each name answers its own question rather than pretending the numbers differ. Verified: `lua tests/wiring_test.lua` **55 checks**, `lighting_test` 125 (12 parity vectors), `material_test` 107 (23 parity vectors), every suite in the repo green, and SHANKPIT's `make test-env-parity` still asserts the shared fixtures from the C. NOT done, named: nothing here has run in a place -- `src/noobtopia.lua` is Luau, so it cannot even be syntax-checked on this box, and no service write has been observed.

- **feat(merge): the engine's recent upgrades are in the Roblox half now -- the environment matrix and the material vocabulary, with parity fixtures BOTH repos assert.** SHANKPIT's lighting bug was real: weather, time of day, fog and the ambient slider each only ever SUBTRACTED, so a stormy night at slider 0 collapsed to near-black walls; the fix was one state (`PARENA/stdlib/shankpit/lighting_rules.prn`) that every consumer reads. That and the material vocabulary (`material_rules.prn`: reflection, UV motion, Quake light styles, screen tints) were already C in SHANKPIT and are now Luau here. `src/lighting.lua` resolves a `sky` table into occlusion / bleed / exposure / ambient-floor / emissive / lightning / emitter range+spread, and `Lighting.roblox()` hands a host the 0..1 numbers a Lighting service wants (`nil` fog end when the reading says "no fog" -- a different fact from zero). `src/material.lua` maps the same rules onto what Roblox actually has -- `BasePart.Reflectance` for the sphere-map reflection the C build draws by hand, per-fixture brightness for the light styles -- instead of pretending the two renderers are one. `scripts/gen_rules.sh` emits both from the shankpit stdlib. Verified: `lua tests/lighting_test.lua` **123 checks, 12 parity vectors** and `lua tests/material_test.lua` **103 checks, 23 parity vectors**, asserting `PARENA/stdlib/shankpit/{lighting,material}_parity.txt` -- the same two files `make test-env-parity` asserts from C in SHANKPIT, so a drifting port goes red in one repo instead of two worlds quietly disagreeing. The lighting fixture describes the host's REAL chain (emissive is fed the ambient floor, not the raw occlusion), so a wrong wiring order cannot pass. NOT done, named: nothing assigns these numbers to a Roblox service (no Studio here), and the C-side reflection/light-style draw paths are unverified in this sandbox too.

- **refactor(tournament): the fold comes from the shared `.prn` now — one bracket rule for two worlds.** Publishing the stage meant SHANKPIT needed a bracket too, and two brackets is exactly the place a seeding rule drifts: one world pairs 1-v-4, the other quietly pairs 1-v-2 and nobody notices until a final looks wrong. So the arithmetic moved to `PARENA/stdlib/deadweight/stage.prn` and is emitted here as `src/generated/deadweight_stage.lua` (`scripts/gen_deadweight.sh` now emits four files): `stageSlots` (next power of two, floored at 2, capped at 8), `stageRounds`, `stageOpponent` (the fold) and `stageHigherSeed` (which side advances a drawn match). `src/deadweight_tournament.lua` calls them instead of its own loop, and its test — **56 checks, 0 failed** — was not touched, which is the point: the same hand-derived bracket came out of the generated fold. The other six suites still pass.

- **feat(tournament): THE STAGE — an esports bracket inside NOOBTOPIA, seeded from the ladder's own rating, and every match a real ladder match.** Founder, real-time: *"can we make a stage for esports tournoments inside of noobtopia"*. `src/deadweight_tournament.lua` is the bracket, kept separate from the ladder on purpose (the ladder answers "who can I challenge now"; a bracket answers "who is left, and what happens next", and folding the second into the first would hide the one thing that can go wrong on a stage). **Entrants are the ladder's top N by RATING** — read through `Board.rows`, the same order the board and WOTAN's page use, so the stage cannot seed differently from the table it stands on. **Seeding is the standard fold** (1 plays the last seed), so the top two cannot meet before the final; a short field gets **byes rather than a smaller bracket**, and a bye is recorded as a decided-but-unplayed match so "advance the winner" is one rule everywhere. **Every match goes through `Ladder.challenge` + `Ladder.accept`** — the same path a friendly game takes — so a stage result moves both records, both ratings and the meta, and lands on the leaderboard's ticker; nothing here re-implements a match. **A draw still advances somebody**, by seed order (the higher seed), because a bracket needs a body and a coin flip is worse than a rule a spectator can predict — the match itself is still a real draw on the ladder, so the stage and the table agree about what happened even though only one of them advances. The world plays its own bracket on its own clock (`Room.tick`, one match per `stageInterval`) but **never a match a person is in** — that one waits for the prompt, so a stage game cannot resolve behind the player's back — and the prompt gains a third branch: *"Press E to play your stage match"*. `src/deadweight_ui.lua` gained `buildStage` (a raised platform, two podiums, six risers of stands, and a banner) whose text is rewritten each tick from the bracket's own frame, so what the crowd reads is what the bracket says; `src/deadweight_server.lua` opens the next bracket when ≥3 members are on the ladder and leaves the champion on the banner for a minute. Verified: `lua tests/deadweight_tournament_test.lua` — **56 checks, 0 failed**, hand-derived from the rules rather than read back: a 1200/1100/1050/1000 field seeds 1-v-4 and 2-v-3, an eight-slot fold keeps the top two in different halves and pairs the middle as 4-v-5, a three-entrant stage records exactly **one** bye and offers **one** live match, `advanceByRank` picks the higher seed regardless of seat order, a played stage is **zero-sum** on the ratings and puts every result on the ticker, a finished bracket logs 3 matches for 4 entrants and then offers nothing more, an unfinished round refuses to advance, and an all-equal field falls back to exactly `Board.rows`' own order. `lua tests/deadweight_room_test.lua` — **55 checks, 0 failed**, now including the wiring: a four-member table opens a stage, the frame carries it, the player is seeded into a live match, the prompt offers it, and pressing plays it. The other six suites still pass (287 + 903 + 107 + 65 + 46 + ambient/walk). NOT done, named: **the stage has never been seen** — `deadweight_ui.lua`/`deadweight_server.lua` need Studio, so the parts, the banner and the podiums are written and reviewed, never rendered; a stage is best-of-one with no losers' bracket, no spectator view/camera and no prize beyond the rating it moves; and the bracket is not published to WOTAN yet, so the stage is visible only to the people standing at it.
- **feat(deadweight): the Roblox SURFACE — a table you can sit at, one prompt, and a board drawn from the ladder — and the ratings now live in the LADDER, in BOTH worlds.** Founder: *"byukd the roblox ui and rating in the c ladder"*. **`src/deadweight_room.lua`** is the pure half: four seats, a 45-second offer cycle where a citizen at the table asks a person to play, and ONE prompt that branches in the order that reads naturally — not seated ⇒ sit down, an offer waiting ⇒ accept, otherwise ⇒ challenge the citizen nearest your rating. It also owns declining, leaving, and `frame()` — everything a screen needs (ranked lines, a `YOU` on your own row, the ticker, the prompt text) as plain values, so the host decides nothing. **`src/deadweight_ui.lua`** is the only new file that touches Roblox: a tabletop with a `ProximityPrompt` (the one input a server Script can actually receive — the same constraint `src/noobtopia.lua`'s Punch event documents), and a `ScreenGui` panel the SERVER writes, in the repo's paper/ink palette and `Enum.Font.Code`, with the prompt's `ActionText` rewritten each tick so the button always says what pressing it does. **`src/deadweight_server.lua`** is the glue: a stable per-server seed from `JobId`, three noobs at the table so a lone player always has an opponent, a 0.25 s `Heartbeat` tick, one frame per player from the same room state (two players can never see two different tables), and `PlayerRemoving` ⇒ leave. **The rating moved into the ladder, which is what makes it the same number in C and Luau:** `member.rating` is set from `PARENA/stdlib/deadweight/rating.prn` on join, adjusted zero-sum by the one recorder every finished match goes through (an instant match and a watched one alike), and carried by the save — the board is now a pure VIEW over the ladder's facts instead of its own copy of the number. `tests/deadweight_board_test.lua` was rewritten around that (**65 checks**) and every value is still hand-derived, including C's truncation: a `-70/50` term is `-1`, so 1000 beating 930 gains 15 (a floor-division port would print 14, and a different table for the same server). **A real bug the new room test caught, in the server rather than the test:** citizens were minted as `-100 - index`, and `Ladder.memberForPid` answers -1 for ANY negative pid (the same "-1 means nobody" sentinel `dw_member_for_pid` keeps in C) — so every noob at the table was invisible to the ladder: never ranked, never paid, and every press answered `busy`. Citizens now get synthetic positive pids from a documented base (`1e12`, far above any UserId), `Room.join` refuses a negative pid at the door instead of seating an unreachable body, and `deadweight_server.start` asserts every citizen actually landed on the ladder. Verified: `lua tests/deadweight_room_test.lua` — **46 checks, 0 failed** (seats and seat reuse, the prompt's three branches, a citizen's offer accepted ⇒ record + zero-sum total unchanged, a decline that moves nothing, an offer that cannot outlive its challenge's TTL, and a table of only citizens offering nobody a prompt); `lua tests/deadweight_board_test.lua` — **65 checks, 0 failed**; the four earlier suites still pass (287 + 903 + 107). NOT done, named: **none of these three files has ever run** — no Studio, no place file, no `luau` on this box, so they are written and reviewed, never executed; there is no DataStore (a per-server board resetting with the server is the accepted design, not an oversight); the board is still not published in the schema WOTAN reads; and the card table itself (a match played ON the table, round by round) is not drawn — a press resolves the game.
- **feat(deadweight): the LADDER and a per-server LEADERBOARD — the Roblox half of the internet-of-SHANKPIT shim, with a real Elo.** Founder, real-time: *"we port the internet of shankpit bits so there can be an on server IDUNA and WOTAN leaderboard on ROBLOX until we get a permanent home the leaderboard can be per server and reset its fine it lets players face the noobs and also eachother to climb the elos"*, then *"we dont need iduna i guess just the leaderboard for now whatever you think"*. Three pieces, each verified under a real interpreter. (1) **`src/deadweight_ladder.lua`** is the port of SHANKPIT's `dw_ladder.c`: ONE `challenge` entry point for all four directions, classified from who the two ends are; a challenge book with the same 45-second TTL and the same expiry/member-left sweep; records; the population's meta tally; decks re-crafted by `cp_deck_card` after every match; and `serialize`/`deserialize` handing back PLAIN TABLES (a DataStore's shape) rather than a file. **Pinned by data:** `PARENA/stdlib/deadweight/ladder_parity.txt` carries both a scripted sequence of ladder ops AND the outcomes, both sides EXECUTE THE SCRIPT FROM THE FILE, so neither can drift by re-typing the scenario — `lua tests/deadweight_ladder_test.lua` **107 checks, 0 failed**, identical to `make test-dw-ladder-parity` (2 scripts, 12 outcome lines). (2) **`src/deadweight_board.lua`** is the consumer half, in the shape a Roblox server can actually use: no HTTP daemon and no IDUNA account for a noob here, so the board is built in-server from the ladder's facts, ranked by a rating, and **resets with the server** — ratings live in the module's own table, so one server's population cannot poison another's. Rows sort deterministically (rating desc, wins desc, pid asc) so a re-render never shuffles rows under a cursor, and `snapshot` hands the same fields `dw_net`'s schema 1 carries (entries, population, a bounded match ticker) as plain values. (3) **The Elo is PARENA's**, not a Lua copy: `PARENA/stdlib/deadweight/rating.prn`, emitted to `src/generated/deadweight_rating.lua` — deliberately not textbook Elo (no floats in PARENA v0), but a bounded, zero-sum integer ladder where beating somebody stronger pays more. `tests/deadweight_board_test.lua` runs **370 checks, 0 failed**, every value hand-derived. **Two real bugs found on the way:** `rating-loss` took its term from the loser's side, so the two ends of one match did not add up (a 1000 beating a 3000 gained 24 while the 3000 dropped 8) — fixed in the `.prn`, which is exactly why the number lives in one place; and PARENA's Lua emitter used `//` for `/`, so every negative dividend floored instead of truncating and the two worlds printed DIFFERENT leaderboard numbers for the same server (fixed in the emitter, see its CHANGELOG). Also honest, and asserted rather than hidden: a member that has not played since the meta moved keeps the deck it was dealt — the same staleness the C ladder has — so the save round-trip asserts byte-identical decks for the members who DID play and asserts determinism of the crafting function for everybody. NOT done: the Roblox SURFACE (a table, a ProximityPrompt, a board GUI — this is the data behind one), publishing this board in the schema WOTAN reads, and the C ladder does not yet carry a rating (the `.prn` is emitted to Luau; wiring `dw_rating.c` is one build away and named).
- **feat(deadweight): the SEQUENCER runs here — the card game is now a game, not just a rule set, and the two worlds are pinned to the same matches.** Phase 1 of the port. `src/deadweight_game.lua` is the round-by-round game ported from `SHANKPIT/packages/simulation/dw_match.c`, driven entirely by the generated modules: 20 hull, 2 energy (+2 a round, capped 6, +1 for passing), 3 credits (+1 a round), 4-card hands from a 16-card deck, all 32 effect channels in both phases (cancel/halve/immune/lifeline/bypass/copy in pass A, bonus/pierce/reflect/true in pass B, then the phase-2 seat changes and the end-of-round burn/regen), bankruptcy below -6, lifeline at 1, and the 100-round draw. It is a DATA module — no `workspace`, no `game`, no `wait` — the same layering `src/wander.lua` and `src/big_o_witness.lua` already use. **The parity claim is now data, not intention:** `PARENA/stdlib/deadweight/match_parity.txt` holds five whole matches (seed, each seat's path/win-rate/meta inputs, aggression, and every round's cards, hulls, energy, credits and damage), written and read by SHANKPIT's `dw_match_parity_test.c` (`make test-dw-parity` / `make regen-dw-parity`) and asserted here by `tests/deadweight_match_test.lua` — **903 checks, 0 failed, 117 rounds identical**. **Two real bugs found by that comparison, one in each world:** (1) PARENA's Lua emitter lowered `if` to `(cond and then or else)`, so a FALSE branch inside a nested Bool ladder fell through into the next `or` and `fx-cond-ok` answered true whenever the ladder's final `roll >= PP` passed — fixed in PARENA by lowering to an IIFE, see its own CHANGELOG; (2) SHANKPIT's sequencer chose each seat's card BEFORE the round dealt, so it read the previous hand — and on a fresh match four zero-filled slots, meaning round 1 played card 0, a card neither seat held. Both sequencers now split a round into BEGIN (clock, economy, deal, DISABLE) and FINISH, with the policy choosing in between. Also asserted here: the same seed plays the same match twice, `playOut` and a stepped round agree, no card that is not in the catalogue ever appears in a transcript, hulls never climb above 20, energy stays in 0..6, a pass-only match runs to the 100-round cap and is a draw, and every crafted deck is sixteen real cards with something playable on 2 energy. NOT ported yet, in order: the **ladder** (challenges in four directions, records, the meta tally), the **Roblox surface** (a table, a prompt, a board GUI), and publishing to the same schema WOTAN reads. `docs/DEADWEIGHT_PORT.md` has the phases and the two remaining risks (Luau's doubles, and 5.4 not being Luau).
- **feat(deadweight): DEADWEIGHT's rules and its citizen policy now run here, emitted from the SAME PARENA source SHANKPIT compiles to C.** Founder: *"start porting the whole thing to NOOBTOPIA clone it down use PARENA build out any missing lua glue"*. The port is not a rewrite: `scripts/gen_deadweight.sh` emits `src/generated/deadweight_rules.lua` (105 cards, the kind triangle, every cost/power/credit, the packed fx engine, the match constants — 68 functions) and `src/generated/deadweight_policy.lua` (win rate, identity, the answer to a meta, card scoring, deck crafting) straight from `PARENA/stdlib/deadweight/{card_rules,citizen_policy}.prn`, which SHANKPIT emits to `dw_rules.c`/`dw_citizen_rules.c`. **The glue had to be built first, in PARENA:** the Lua target could not express `let` (the policy's binding vector fell through to the call branch: "unsupported expression form"), and `(do ...)`/`set!`/loops/`def`/`defstruct`/`match`/`case` silently emitted `M.do(1, 2)` — plausible-looking Lua that only an interpreter rejects. `let` now lowers to an immediately-invoked function (one expression, `local`s in source order, so a later binding reads an earlier one) and those statement forms refuse by name. Verified: `lua tests/deadweight_test.lua` — **287 checks, 0 failed**, every expected value hand-derived from the `.prn` rather than read back: hull 20 / energy 2 / credits 3 / four-card hands / 100 rounds / 105 cards, the base line's tier→cost 1/2/4, the triangle total and antisymmetric with Offense beating Operations and Defense beating Offense, a pass dealing nothing, legality by energy and credits, the policy's Laplace smoothing (0-0 is 500, 1-1 is 666, 0-4 is 166), identity/answer kinds, a 400-permille meta not counting as a meta, an unplayable card masked -1, ties with pass passing, slot 0/1/3/13 of a crafted deck, and every crafted id for every path and both ends of a record inside `numCards()`. `luac -p` accepts both generated modules; the existing `ambient_test.lua` and `walk_test.lua` still pass. NOT ported yet, named in `docs/DEADWEIGHT_PORT.md`: the **sequencer** (`SHANKPIT/packages/simulation/dw_match.c` — 32 effect channels, bankruptcy, 100-round draw), the **ladder** (challenges/records/meta), the **Roblox surface** (table, prompt, board GUI), and publishing the same schema WOTAN reads. Two real risks recorded there: Luau's numbers are doubles (32-bit-overflow rules would differ — the seed-mixer bug is precedent), and plain Lua 5.4 is not Luau.

## 2026-10-31

- **fix(ambient): `nextSeed` now matches the C host exactly, and the tests pin it.** `src/ambient.lua` carried the 1103515245 mixer, which needs ~61 bits while a Luau number holds 53 — so `Ambient.nextSeed` and SHANKPIT's `ambient_life_next_seed` returned different values above a seed near 2^31 and the two worlds talked over different lines. It is now MINSTD (`* 48271 mod 2^31-1`), identical to the C, with a negative seed clamping to 0. Verified: `tests/ambient_test.lua` pins the same four vectors `SHANKPIT/packages/simulation/ambient_life_test.c` pins (0, 42, 999999, 2147483646 → `2147435376`) and runs clean; `tests/walk_test.lua` still clean. NOT verified, named: plain Lua 5.4 has 64-bit integers, so a passing run here is *not* proof of Luau behaviour in general — only these four vectors are arithmetic-exact in both.

- **feat(wander): where a noob drifts, and when, is now PARENA's decision — and the Luau half runs for real.** `src/wander.lua` is the headless host: integer world units, a permille credit, no `Vector3`, no `wait`, no `game` — so `tests/walk_test.lua` can run it under a plain interpreter. The Roblox host (`src/noobtopia.lua`) now walks by it, replacing a `math.random() < 0.02` nudge on a single axis that could not be shared with anything; direction comes from the shared heading, magnitude from `arena_rules`'s own `stepSpeed`, so slippery physics still applies. `tests/walk_test.lua` asserts the same `PARENA/stdlib/noobtopia/walk_parity.txt` rows SHANKPIT's `make test-walk-rules` asserts, plus the properties a designer means by "it wanders": a startled noob frozen at 0 permille, a curious one pausing least and roaming furthest, a leash that holds over 3000 ticks, a leg that terminates, and the same seed walking the same path twice. Verified: `lua tests/walk_test.lua` — 13 parity vectors, 0 failed; `lua tests/ambient_test.lua` still clean. **A bug found by finally executing this repo:** the seed mixer in `src/ambient.lua` (`* 1103515245`) needs ~61 bits, and Luau numbers are doubles (exact to 2^53), so it silently diverges from the C above a seed near 2^31 — seed 2147483646 yields `2087949151` exactly, `2087949312` in double arithmetic. `wander.lua` therefore uses MINSTD (`* 48271 mod 2^31-1`); `ambient.lua`'s own mixer is left untouched and named in `../docs/THREE_WAY_MERGE.md` §3b, because changing it moves every existing ambient draw. NOT verified, named: **Roblox itself** — no Studio, no place file, no publishing; plain Lua 5.4 is not Luau (it has 64-bit integers where Roblox has doubles), so the test run proves the rules and the integration but never the `workspace` host.
